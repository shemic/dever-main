# HTTP/2 性能基准

N5 已完成 HTTP/2 服务端、客户端和连接池的功能接入，但现有独立二进制基准仍只测 HTTP/1.1。当前阶段为 HTTP/2 建立可重复的小机器性能证据，不凭功能测试或理论值宣称性能提升。

## 需求

- 扩展现有显式运行的独立二进制基准，新增 HTTP/2 suite；保留已有 HTTP/1.1、异步和长连接基准的语义及历史报告。
- 覆盖明文 prior knowledge 和 TLS ALPN 两种 HTTP/2 传输，统一比较原生 Dever 程序、直接 `dever-runtime` 和原生 Hyper 三种实现。
- 负载模型必须把物理 TCP 连接数与每连接并发流数分开。每个报告明确记录协议、TLS、物理连接数、每连接请求槽、总请求槽、服务端流/窗口配置和正文大小。
- 至少覆盖单连接多流和多连接多流；请求必须校验状态码、Content-Type 和完整正文，所有计划、发送、完成、失败及丢弃请求均可核对。
- 记录实际成功吞吐、总延迟/排队延迟/请求延迟的 p50/p95/p99，以及服务端和客户端 RSS、PSS、峰值、线程、FD、CPU 和 cgroup 内存/OOM 数据。
- 同一服务进程上重复建立、使用和关闭 HTTP/2 连接，记录每轮断开后的 FD/RSS 差值，验证物理连接能够回收且内存不按轮持续增长。
- 生成按实现、传输、路径、速率和连接拓扑分组的中位数摘要，同时保留逐 case 原始样本和失败时已完成的数据。
- 完成 1 worker、1 服务 CPU、128 MiB、无 swap 的正式矩阵，并完成 64 MiB 下的 Dever 活跃 HTTP/2 代表场景；负载端使用独立 CPU且不计入服务预算。

## 约束

- 本任务只改基准夹具、基准对端、运行器、定向测试和对应性能文档；不修改 `crates/dever-runtime`、编译器或语言公共 API。基准揭示的生产瓶颈另建优化任务，避免边测边改导致基线失效。
- 复用仓库锁定的 Hyper 1.11.1、h2 0.4.19、rustls 和现有进程/cgroup 采样器，不引入新的协议栈或压测依赖。
- HTTP/2 明文只使用 prior knowledge；TLS 只协商 `h2`，不降级 HTTP/1.1。HTTP/1.1 每连接请求槽固定为 1，HTTP/2 只测复用连接，不测每请求新建连接。
- 服务端与客户端固定使用 N5 默认值：每连接 16 流、65535 字节单流接收窗口、262144 字节连接接收窗口，以及运行时已有的 16 KiB frame/send-buffer 上限。
- `/plain` 用于小响应调度和协议开销，`/bytes` 使用 65536 字节正文并跨越默认单流窗口；`/json` 不进入正式矩阵，因为当前夹具只返回预制 JSON，信息与小响应重复。
- 不设与机器无关的绝对 QPS 或内存门槛。错误、OOM、计数不守恒和 FD 未回落属于失败；容量丢弃与相对性能只作为结果，不伪装成通过或失败阈值。
- 仅运行本任务的 Python 单元测试、独立 loopback smoke、必要的离线 release 构建和显式有界性能命令；不运行全量测试，不替换全局二进制，不接触已有服务，不提交 Git。

## 验收标准

- [x] HTTP/1.1 旧入口仍通过现有独立 Python 对端测试；HTTP/2 smoke 证明一条实际物理连接承载至少 16 个并发请求槽，明文和 TLS 均完整成功。
- [x] 构建清单包含 `http2`/`https2` Dever 产物、HTTP/2 配置及所有二进制指纹；运行阶段只使用清单中的已构建产物。
- [x] `http2` suite 覆盖三种实现、两种传输、`/plain` 与 `/bytes`、`1 x 16` 与 `4 x 16` 两种拓扑，并保存可核对的逐 case 数据与聚合摘要。
- [x] `http2-recovery` suite 在同一服务进程上完成至少 10 轮连接周期；每轮请求正确，断开后 FD 回到 READY 基线，且报告保留 RSS 变化序列。
- [x] 128 MiB 正式矩阵中无请求错误、无 OOM；丢弃请求如实报告。64 MiB 代表场景无 OOM，并报告峰值而非只报告进程 RSS。
- [x] 文档写明运行命令、环境、矩阵、限制和实测结论；不得将 HTTP/2 结果外推为所有后端负载或真实网络的性能保证。
- [x] 定向测试覆盖参数校验、计数守恒、连接拓扑字段、摘要分组、H2 明文/TLS 正文校验、进程失败和连接回收；相关检查全部通过。

## 排除项

- RFC 8441 WebSocket-over-HTTP/2、h2c Upgrade、HTTP/3、服务器推送、非空 trailers、HTTP/2 客户端自动重试。
- 小时级 soak、跨主机网络、丢包/限速故障注入、真实公网站点和多平台硬件矩阵。
- 本阶段根据一次测量直接改写运行时热路径或承诺固定的 Fiber/Go 对比数字。
