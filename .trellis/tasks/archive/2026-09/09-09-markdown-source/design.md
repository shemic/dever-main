# 设计

## 归属与复用

源码格式和 Markdown 内容区间由 core 拥有。使用 CommonMark 解析库识别真实顶层围栏，避免自造解析器误执行列表、HTML 或外层示例内的伪代码。新依赖仅用于编译器，不进入最小运行时。

SourceFile 保留原文，词法 token span 使用原字节位置。Markdown 提取不能让缓存、诊断、运行故障指向合成文件。词法/格式化共用程序区间；语义包路径接受 `.dever.md`，重复检测沿用声明注册。

## 格式化

先解析全包，验证完整声明不跨围栏。复用 AST 格式化方法，按块选择包头/声明/注释生成内容，原位替换内部文本。不能合并代码块或移动说明。CLI 快照检查与 staging 原样复用。

## 分工与契约

主代理负责 CLI 文案、实际 CLI 验证、示例、文档、规范与任务记录。实现代理负责 core/加载/解析/格式化、必要依赖和 core 定向测试。完成后独立审查，主代理复核关键证据。

程序围栏须顶层、闭合，信息字符串为 `dever`；无标记及其他语言只展示。每个类型、函数分句和 package 头完整位于一块内。若不支持缩进围栏，应明确诊断，不静默改变归属。
