# Dever Markdown 程序源码支持

## 目标与确认决定

用户希望用 Markdown 组织易读的 AI 程序，继续由 Dever 类型与契约约束执行。2026-09-09 用户批准同时保留 `.dever` 和 Markdown 源码，并明确选择 `.dever.md` 后缀。

- `.dever` 行为兼容；`account/user.dever.md` 对应 `account.user` 包。
- 标题、说明、表格不参与程序定义；只有标为 `dever` 的顶层围栏代码块属于程序，按顺序处理。代码保留完整 Dever 包、类型和函数声明。
- 一个文件拥有一个包；格式可跨包混用，同包重复必须报错。
- 复用现有语法、语义、契约、API 与原生编译路径。
- 诊断和运行故障定位到原 `.dever.md` 文件及准确行列。
- `fmt` 只格式化程序代码块，保留其它 Markdown 和围栏；整批检查后逐文件原子写入规则不变。

## 验收

1. 只加载 `.dever`/`.dever.md`，普通 `.md` 中的示例忽略。
2. 同一程序两种格式的执行结果一致；混用包可调用，重复包、类型错误、分句缺失、失败义务仍拒绝。
3. 多代码块、中文、不同换行、注释和原生故障位置正确；普通示例、嵌套围栏、引用、列表与 HTML 内的伪程序不执行。
4. 程序围栏闭合，各块包含完整顶层声明（允许纯注释或空块）；无程序块、跨块声明报错，避免格式化移动代码跨说明。
5. 格式化只更新代码块内部、幂等；语法或程序结构错误时无文件改写。
6. 提供可读的结算 Markdown 示例，更新语言说明和过时草案。

## 范围与验证限制

不增加新语言语法、浏览器运行时、编辑器扩展或多语言执行。不改无关文件，不提交或安装全局命令。只跑离线定向检查和自有临时程序，不跑全量、集成测试或现有服务。开发依赖获取明确记录，最终程序编译保持离线。
